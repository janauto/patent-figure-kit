# Plan Studio：人工二次操作的浏览器界面 · 实施方案

**一句话定位**：Web 界面是 `figure-plan.json` 的**第三位作者**——
LLM 出初稿，人在浏览器里点选修正（拆哪几张图、哪个零件叫什么、标不标号），
脚本照旧确定性渲染。**界面的唯一产物仍然是那份 plan，不新增任何几何自由度。**

这不是在 v2 架构旁边另起炉灶，而是 v2 架构自带的空位：契约把「出图意图」压缩成了
一份 schema 严格的 JSON，谁来写这份 JSON 本来就是可替换的。人工点标只是换了一位作者，
`validate → render → qa` 三道闸门一个都不动，跨模型一致性的 M4 命题对人工路线同样成立
——**人点出来的 plan，也必须在任何机器上渲出同一张图**。

---

## 1. 人的工作流（走一遍）

```
启动:  python3 scripts/plan_studio.py ASM.stp            ← 一条命令，自动开浏览器
        │  后台: analyze（有缓存）→ 导出 GLB → 可选: 请 LLM 出 plan 初稿
        ▼
① 拆分  3D 视图里零件按「图」着色。右侧三张拆分建议牌（共轴/栈序/尺寸，
        来自 assembly.json:split_suggestions，脚本算的）——点一张即预填。
        点零件 → 按数字键或拖进图卡改归属。图卡实时显示「标记数/20」，超限变红。
② 命名  零件表逐行填中文术语；同名多实例自动合并一行；
        拖动行序 = 附图标记发号顺序；once/all/none 三态开关。
        「批量不标」按钮：按尺寸阈值把小件（螺钉垫片）一键设为 none。
③ 渲染  点「渲染」→ 后台跑 render CLI（含 QA 闸门）→ 每张图出 SVG 预览
        + 12 项 QA 红绿灯。失败项直接显示 hint（和给模型看的是同一句话）。
④ 修正  照 hint 改（拆图/改术语/改 density）→ 重渲。预览里点某个标记数字，
        3D 视图里对应零件高亮——核对「7 号到底是不是上盖」不用来回数。
⑤ 导出  全部图 QA 通过后才出现「导出」：DXF + DWG + reference-numerals.json
        +「附图标记说明」文本（直接粘进说明书）。
```

关键体验点：**人始终在「意图层」操作**（这个零件归哪张图、叫什么、标不标），
永远碰不到坐标、字高、角度这些「版面层」的东西——那些是渲染器的事，
也正是 v1 事故里模型不该碰、人同样不该碰的东西。

## 2. 每个点击动作落到 plan 的哪个字段

| 界面动作 | plan 字段 | 说明 |
| --- | --- | --- |
| 把零件拖进某张图卡 | `figures[].members` | 写**显式零件名清单**，不自动生成 glob（防误伤）；用户要 glob 得自己敲 |
| 新建/删除图卡、改图题 | `figures[]` 增删、`caption` | `kind` 用装配/分解两态开关 |
| 术语列输入 | `terms[].term` | 失焦即调 validate，件号形态当场标红（`E_TERM_LOOKS_LIKE_PART_CODE` 前置到输入框） |
| 拖动术语行序 | `terms[]` 顺序 | 行首实时显示将获得的号码——号码仍是脚本发的，界面只是预演 |
| once/all/none 开关 | `terms[].label` | |
| 视图/密度/角度下拉 | `layout.view / density / axis_angle` | 只有 schema 里的枚举；`axis_angle` 默认 `"auto"`，下拉里也是 auto 置顶 |
| 工程明细表开关 | `layout.engineering_table` | 默认关，打开时界面明示「仅内部评审，文件名带 _engineering」 |

**界面上不存在的东西**：坐标输入框、字高输入框、间距滑块、颜色选择器、
「跳过 QA 强制导出」按钮。护栏不是靠自觉，是靠这些控件根本不存在。

## 3. 系统架构

```
┌─ 浏览器（仅 127.0.0.1）────────────────────────────────┐
│  零件树+搜索 │      3D 视图(three.js)      │ 图卡+术语表 │
│  拆分建议牌  │  GLB, 点选/框选, 按图着色    │ QA 红绿灯   │
│              └── 底部: 各图 SVG 预览（标记可点击联动 3D）│
└──────────────┬────────────────────────────────────────┘
               │ REST（本机回环，STEP 涉密不出机器）
┌──────────────▼────────────────────────────────────────┐
│  scripts/plan_studio.py   FastAPI + uvicorn（已装）     │
│  GET  /api/assembly   analyze 结果 + GLB（按 STEP sha 缓存）│
│  GET/PUT /api/plan    读写 plan.json；每次 PUT 即跑 validate│
│  POST /api/render     subprocess 调 render CLI → SVG+qa.json│
│  GET  /api/progress   渲染进度（大装配体 HLR 要几十秒）      │
│  POST /api/export     仅当全部 QA 通过；DXF→DWG 走既有转换器 │
└──────────────┬────────────────────────────────────────┘
               │ 全部经由既有 CLI（subprocess），不 import 内部符号
        analyze / validate / render(内含QA) / convert   ← 与模型走的完全同一条路
```

三条架构纪律：

1. **服务器对渲染链路只走 CLI**。人工路线和模型路线过的是同一套闸门、
   同一批错误码、同一份 hint 文案——两条路线永远不会各长各的。
2. **只绑 127.0.0.1**。STEP 是涉密模型，不出本机；要局域网协作是另一个决定（见 §7）。
3. **plan.json 是唯一状态**，没有数据库。每次保存在 `.plan-history/` 落一个
   时间戳快照，撤销/重做在前端内存里做（plan 很小，整份快照即可）。

## 4. 关键技术点（本机已验证 ✅ / 待做）

## 5. 分期与验收

**W1 · 最小闭环**（先能用起来）
- GLB 导出 + 缓存；FastAPI 五个端点；三栏界面：零件树 / 3D 点选着色 / 图卡+术语表
- 渲染 + SVG 预览 + QA 红绿灯；导出闸门
- **验收**：用合成夹具，从零起步纯手工做出「1 张总装 + 1 张分解」并导出，
  全程不碰命令行；产出 plan 经 CLI 重渲，`normalized_digest` 与界面导出一致

**W2 · 顺手度**（省下重复劳动）
- 拆分建议牌一键预填；拖拽排序；批量 label:none；撤销/重做
- 预览标记 ↔ 3D 零件双向高亮；未分配零件常驻提醒（防漏画）
- **验收**：对 164 实例的真实装配体，人工完成 4~5 张图的拆分标注在 30 分钟内

**W3 · 增强**（可选）
- 「AI 建议」按钮（术语初译、分组初稿——只写 plan 草稿，人确认后生效）
- 两份 plan 并排 A/B 渲染对比；摘要附图模式（配合 spec 里那条缺口一起做）

## 6. 与既有工作的关系

- 对 `scripts/patent_figure/*` **零改动**；新增的只有 `scripts/plan_studio.py`、
  `webui/`（前端源码+构建产物）、occ_backend 里一个 `export_glb()`（约 40 行）。
- SKILL.md 的禁令约束的是**模型**；Plan Studio 是仓库内的第一方工具，与 CLI 同级。
  在 SKILL.md 里补一行：「人工修 plan 请用 plan_studio，不要让模型代点」。
- 千问办公评测不受影响：那条测的是模型路线；本界面测的是人工路线，两条路线共享闸门。

## 7. 需要拍板的三件事

1. **单机版还是局域网版？** 本方案按单机（127.0.0.1）设计——STEP 不出机器。
   要给同事共用就得加登录和文件隔离，工作量翻倍，建议先单机。
2. **前端要不要上 React？** ~~建议上，构建产物入库~~ → **已裁决：不上，
   用免构建的 vanilla ES modules + vendored three.js（importmap）。**
   压倒性理由来自「脱敏入公开仓库」这条要求本身：入库的必须是**未混淆的源码**，
   人和工具都能逐行审计有没有夹带涉密信息；minified 的 React 构建产物没法做这种检查。
   附带收益：仓库不引 node 工具链、用户零构建即用、离线可用（vendored，不走 CDN）。
   代价是状态逻辑手写（plan 是一份小 JSON，可控）。three.js 按 MIT 协议随附 LICENSE 与版本号。
3. **放哪个仓库？** 建议就放 `patent-drawing-dwg-cleanup/webui/`（与 skill 同进退）；
   但注意仓库是公开的——前端代码无涉密问题，运行时数据（STEP/GLB/plan）都在
   用户本地工作目录，不进仓库。

## 8. 风险如实说

- **GLB 名字往返**是唯一可能翻车的技术点（STEP→XCAF→glTF 三层命名映射）。
  先花半小时做 spike，翻车则退路是 trimesh 手写 GLB（多 ~80 行，无平台风险）。
- 深腔装配体在 3D 里点不到内部零件——零件树点选是永远可用的兜底，两者联动。
- 渲染是同步子进程，W1 阶段连点两次「渲染」要做防抖/排队，否则缓存目录会并发写
  （occ_backend 的缓存写入者并发不安全，实现报告里记过这条）。
