# 专利附图 Skill 迭代规划 v2

**目标**：把出图从「大模型现写脚本」改成「大模型填一份计划、脚本负责全部几何与版面」。
模型只保留两件事——**结构拆解规划**和**结构的文本化分析**；其余一律由脚本确定性完成。
衡量标准不是"看起来好一点"，而是：**同一份计划在任意 LLM 上产出同一张图**。

适用范围：`patent-drawing-dwg-cleanup` 的 **3D CAD（STEP）生成路线**。
已有的 DXF 清洗、DWG 转换、校验三条路线本次不改。

---

## 1. 现状基线

以一次真实运行为基线：某三轴驱动模组，STEP 装配体，筛出 **90 个零件实例 / 68 个不同零件**，
经 `cad_hlr_to_dxf.py` 的内部函数 + 模型现写的 `gen_exploded.py` 出图。

四个实测硬指标（直接读产出 DXF 统计，非目测）：

| 指标 | 实测 | 说明 |
| --- | --- | --- |
| 几何面积占版率 | **13.5%** | 图形只占整张图 2576×8791 中的一小块 |
| 明细表高度占版率 | **82.3%** | 版面主体是一张 68 行的零件明细表 |
| 附图标记重叠率 | **97%**（90 个标记中 87 个被压或压别人，242 对相交） | 标记基本不可读 |
| 文字实体分布 | 367 个 TEXT 中 **351 个在 TABLE 图层（96%）** | 图上绝大部分文字不是附图标记 |

补充事实：明细表 NAME 列直接写的是**内部件号**（形如 `<厂内编码>-<图号>_n_n`），
90 个引线里出现重复编号（同名零件多实例各画一条引线各标一次号）。

**结论：这张图不能作为专利附图提交，也不能作为工程图使用。** 不是"效果差一点"，是不可用。

## 2. 三个根因

三个根因性质不同，修法也不同，不要合并成一句"模型幻觉"。

### R1 · 能力缺口：CLI 表达不了需求，模型只能自写脚本

`cad_hlr_to_dxf.py` 的 CLI 提供 `--explode-axis / --axis-angle / --table / --caption`，
**但没有"逐件引线 + 附图标记"的能力**，也没有多图拆分能力。

于是模型写了 `gen_exploded.py`（约 170 行），`sys.path.insert` 后直接 import 脚本内部符号
（`View / explode / hidden_line / load_step / roll_for_axis / LAYERS`），
自行实现了引线几何、标记落位、表格列宽、字高比例、编号排序。

**这一整个文件就是幻觉面。** 里面每一个数字（`AXIS_ANGLE=152`、`GAP_FRAC=0.045`、
`margin = size*0.012 + h*2.2`、`cols=[0.085,0.335,0.085,0.495]`）都是模型当场发明的版面常数，
换一个 LLM 会发明另一组，结果必然不一致。

> 这是**结构性**问题：只要 CLI 覆盖不到需求，任何模型都会退化成写脚本。堵不住，只能补上。

### R2 · 规范错误：参考文档把机械装配图规范当成了专利附图规范

`references/cad-source-to-drawing.md` 第 6 节「Sheet conventions」明确规定：

> Part table — `NO. | NAME | QTY | REMARK`，置于左下，REMARK 写固定方式

这是 GB 机械装配图的约定，**不是专利附图的约定**。中国专利附图的通行要求是：
图中除必需的词语外不应含其他注释，零件用**附图标记**指示，标记须与说明书中的技术名词对应
（见《专利法实施细则》关于附图的条款及《专利审查指南》相应章节——落地前请核对现行条文原文，
本文不引用具体条号）。

由此产生三个后果：

1. 图上出现了专利附图不该有的 68 行明细表，占掉 82.3% 版面；
2. 明细表泄露内部件号——公开文本里出现厂内编码，是**保密问题**，不只是美观问题；
3. 附图标记退化成"明细表序号"，与说明书术语没有任何映射，
   写说明书时还得人工再做一遍对应。

> **即使模型零幻觉、严格照文档执行，也会产出一张不合规的图。** 这是规格 bug，不是模型问题。

### R3 · 没有质量闸门：不合格也能交付

现有 `validate_clean_dxf.py` 只查两件事：线型是否 CONTINUOUS、有无可疑数字文本。
它对"标记 97% 重叠""几何只占 13.5%""图上有明细表"**全部通过**。

所以这张图一路走到了 outputs 目录，还生成了可编辑文本 / 轮廓文本两套 DWG+DXF。
**校验器测的是文件格式，不是图的可读性。**

### 附：标记为什么必然重叠（定量机理，说明这不是调参能解决的）

`explode()` 把零件沿轴按投影足迹**一维**首尾排开。90 个实例排成一条串：

- 爆炸串对角长 **2707**
- 单件槽位 = 2707 / 90 实例 ≈ **30.1**
- 标记字高 = `size * 0.022` = 2382 × 0.022 ≈ **52.4**
- **字高 / 槽位 = 1.74**

**每个附图标记比它要标的零件槽位还大 74%。** 在这个布局下，无论怎么调 `margin`、
怎么改引线角度，标记都必然互相碾压。真正的解法有三个，都必须由脚本实现：

1. **多图拆分**——68 件不该画在一张图上，应拆成"总装图 + 各组件分解图"；
2. **二维排布**——一维串换成沿轴分段 + 段内错列，或按组件成组排布；
3. **确定性避让**——候选位打分选位，而不是固定偏移。

这三件事都是几何算法，恰恰是最不该交给 LLM 手写的部分。

## 3. 目标架构：一份 JSON 契约，把自由度关进笼子

### 3.1 职责切分

| 环节 | 谁做 | 产物 |
| --- | --- | --- |
| 读装配体、算包围盒 / 轴线 / 装配栈序 / 共轴分组 | 脚本 | `assembly.json` |
| **拆解规划**：分几张图、每张图收哪些件、按什么顺序 | **模型** | `figure-plan.json` |
| **文本化分析**：件号 → 中文技术名词、图题、必要说明 | **模型** | `figure-plan.json` |
| 计划合法性检查 | 脚本 | 通过 / 带修复提示的错误 |
| 编号分配、视图求解、HLR、版面、引线、避让、拆图、出 DXF | 脚本 | `图N.dxf` |
| 可读性与合规质检 | 脚本 | `qa.json` + 预览 PNG |
| DXF → DWG | 脚本（沿用现有） | `图N.dwg` |

**模型的输出只有一个文件：`figure-plan.json`。** 不允许有第二个模型产物。

### 3.2 `figure-plan.json` 契约

分两半，两半的约束强度不同：

**A. 语言学部分（模型的真实价值所在，自由但受 schema 约束）**

```jsonc
{
  "schema": "patent-figure-plan/1",
  "source": { "step": "…/asm.stp", "include": ["<件号前缀>*"], "exclude": [] },

  // 全局术语表：零件选择器 -> 中文技术名词。顺序即附图标记的发号顺序。
  // 模型只写名词，不写号码。
  "terms": [
    { "selector": "<前缀>-A01_1_1", "term": "底座",        "label": "once" },
    { "selector": "<前缀>-H51*",    "term": "紧固螺钉",    "label": "none" },
    { "selector": "<前缀>-Z01_1_*", "term": "回转轴组件",  "label": "all"  }
  ],

  // 拆解规划：一张图一个条目
  "figures": [
    { "id": "fig1", "caption": "整体结构示意图",
      "kind": "assembly", "members": ["*"] },
    { "id": "fig2", "caption": "俯仰轴组件分解示意图",
      "kind": "exploded", "members": ["<前缀>-A0*", "<前缀>-Z01_1_*"] }
  ]
}
```

- `selector` 用 glob，**必须能在 `assembly.json` 中命中**，命不中即报错；
- `term` 是中文技术名词，**禁止填内部件号**（校验器按正则拒绝）；
- `label` 三态解决重复编号问题：`once`（同名件只标一次）/ `all`（每个实例都标）/ `none`（标准件不标）；
- `terms` 的**顺序**决定发号顺序，模型可以排序，但**不写号码**。

**B. 图面参数部分（枚举或夹紧区间，不接受自由数值）**

```jsonc
"layout": {
  "view": "iso",                 // 枚举：iso|front|top|right|…
  "explode_axis": "z",           // 枚举：x|y|z|auto
  "axis_angle": 152,             // 夹紧到 [120,180]，越界改成边界值并记录
  "density": "normal",           // 枚举：compact|normal|loose —— 不暴露 gap_frac
  "max_labels_per_figure": 20    // 上限硬约束，超了校验器要求拆图
}
```

> **原则**：凡是能用枚举表达的，不给浮点；凡是要给浮点的，给区间并夹紧。
> 版面常数（字高比、列宽比、引线长度、避让边距）**完全不在契约里**，只存在于渲染器内部。

### 3.3 编号规则：脚本发号

- 号码由脚本按 `terms` 顺序发放，从 1 连续编号；
- **一个项目一张全局标记表**，`fig1`/`fig2`/`fig3` 中同一零件号码相同；
- 输出 `reference-numerals.json` + 一段可直接粘进说明书的
  「附图标记说明：1—底座；2—回转轴组件；…」文本。

这样做同时解决三件事：模型不再有编号自由度、跨图编号一致、说明书标记说明自动生成。

### 3.4 工作循环

```
analyze  →  plan  →  validate  →  render  →  qa  →  convert
   ↑                     │                    │
   └──── 失败时：只允许改 figure-plan.json ────┘
```

失败处理规则写死在 SKILL.md 里：

- 校验器 / 质检器返回**机器可读错误 + 修复建议**（例：
  `E_TOO_MANY_LABELS: fig1 有 68 个标记，上限 20 —— 建议按共轴分组拆成 3 张图，候选分组见 assembly.json:groups`）；
- 模型**只能修改 JSON 重试**，不得改脚本、不得写新脚本；
- 连续 3 次修不好 → **停下来报告能力缺口**，不许自己发明实现。

### 3.5 明令禁止条款（写进 SKILL.md，是硬约束不是建议）

1. 禁止编写任何临时生成脚本（`gen_*.py` 一类）；
2. 禁止 `sys.path.insert` + import 脚本内部符号，脚本只能通过 CLI 调用；
3. 禁止在 plan 里出现版面常数、坐标、字高、颜色；
4. 禁止手填附图标记号码；
5. CLI 表达不了的需求 → **报告缺口并停止**，由人决定是否扩 CLI。

## 4. 分期计划

### P0 · 规格纠偏 + 契约冻结（不写渲染器也能立刻止血）

改文档和 CLI 表面，不动几何算法。

- `references/cad-source-to-drawing.md` §6：把「专利附图规范」和「工程装配图规范」拆成两张表。
  专利附图默认 **无明细表、无内部件号、只有附图标记与图题**；
  明细表降级为 `--engineering-sheet` 显式开关（供内部评审用，非交付件）。
- 新增 `references/patent-figure-spec.md`：附图标记、引线、图题、字体、多图关系的落地规范
  （落地前核对现行《专利审查指南》条文原文再定稿）。
- 新增 `schemas/figure-plan.schema.json` 与 `schemas/assembly.schema.json`。
- SKILL.md 重写为「契约 + 循环 + 禁止条款」，把散落的 how-to 全部下沉到 references。
- `cad_hlr_to_dxf.py` 增加 `--analyze out.json`：输出零件表、包围盒、主轴、共轴分组、装配栈序，
  并给出**候选拆图分组建议**（脚本算，不是模型猜）。

**P0 验收**：模型只用 `--list-parts` / `--analyze` 的输出即可写出一份通过 schema 校验的
`figure-plan.json`；文档中不再出现"专利附图要画明细表"的表述。

### P1 · 确定性渲染器

新增 `scripts/render_patent_figure.py`，输入 `figure-plan.json`，输出多张 DXF + 预览 PNG。
把 `gen_exploded.py` 里模型手写的那部分，全部内化成脚本算法：

- **多图拆分**：按 plan 的 `figures` 出图，共享全局标记表；
- **二维排布**：一维串改为沿轴分段 + 段内错列；分段数由零件数与目标占版率反解，不由人给；
- **自适应字高**：字高由「单件槽位」与「目标占版率」反解，**杜绝字高 > 槽位**；
- **确定性标记避让**：每个标记生成候选位（径向 8～12 个），
  按「不压几何 / 不压其它标记 / 引线不交叉 / 靠近零件」加权打分，
  贪心 + 固定顺序回退，**无随机数**；
- **占版归一**：几何按目标占版率缩放到图框，图题固定位置。

`gen_exploded.py` 里能复用的算法搬进来，**但所有魔数变成算法的解，不再是常数**。

**P1 验收**：同一份 plan 连续跑 5 次，输出规范化后哈希一致；基线用例的四个硬指标全部达标（见 §5）。

### P2 · 质检闸门 + 金样 + 环境探针

- 新增 `scripts/qa_patent_figure.py`，把 §5 阈值实现为**会 fail 的检查**，输出 `qa.json`；
- 新增 `tests/golden/`：小型 STEP + 固定 plan + 规范化哈希。
  **DXF 规范化必做**：清掉 handle/`$HANDSEED`、`$TDCREATE`/`$TDUPDATE`、`$FINGERPRINTGUID`/`$VERSIONGUID`
  等易变字段后再哈希，否则金样必然假失败；
- 新增 `scripts/doctor.py`：探测 `cadquery-ocp`（本 skill 实际使用的 OCCT 绑定，pip 可装；
  **不是** conda-only 的 `pythonocc-core`）、`ezdxf`、`jsonschema`、字体
  （`simfang.ttf`/`txt.shx`）、AutoCAD / LibreDWG，输出机器可读能力报告；
  SKILL.md 规定**首次运行先跑 doctor**，缺什么直接报，不许静默降级；
- 新增 `requirements-pinned.txt`，锁死版本——跨机器一致性的前提。

**P2 验收**：把基线那张 DXF 喂给 qa 脚本必须 **FAIL**，且错误项覆盖四个根因症状；金样测试连跑 10 次不抖。

### P3 · 跨模型一致性评测与适配器

- **一份契约，多个薄适配器**：`SKILL.md`(Claude) / `AGENTS.md`(Codex 及通用) / `agents/openai.yaml`
  三者**只写入口和禁止条款，指向同一份 schema 与 CLI `--help`**，不复制任何流程叙述。
  文档一旦重复，模型间就会漂移。
- **评测集**：3～5 个装配体 × 3～4 个运行时（Claude Code / Codex / 千问办公 / 一个开源模型），
  每组跑 3 次，记录：是否自写脚本、plan 校验一次通过率、qa 一次通过率、
  **相同 plan 的输出哈希是否一致**。
- 一致性的准确定义（写进文档避免误解）：
  **相同 plan → 输出规范化后完全一致**；不同模型允许 plan 本身不同，但必须都在 schema 内且都通过 qa。
  一致性目标约束的是渲染，不是规划。

**P3 验收**：自写脚本次数 = 0；跨运行时相同 plan 哈希一致率 100%；qa 一次通过率 ≥ 80%。

## 5. 质检阈值（P2 实现，来自基线实测的反向定义）

| 检查项 | 阈值 | 基线实测 | 来源 |
| --- | --- | --- | --- |
| 几何面积占版率 | ≥ 55% | 13.5% ❌ | §1 |
| 附图标记两两重叠 | = 0 对 | 242 对 ❌ | §1 |
| 标记字高 / 单件槽位 | ≤ 0.6 | 1.74 ❌ | §2 机理 |
| 零件图面包围盒相互重叠（分解图） | = 0 对 | 待测 | 分解图可读性前提 |
| 单图标记数 | ≤ 20 | 68 ❌ | 拆图触发条件 |
| 非附图标记类文字占比 | ≤ 10% | 96% ❌ | §2 R2 |
| 图面出现内部件号 | 禁止（可配置正则清单，如 `^[0-9]{4,6}-[A-Z][0-9]{2}`） | 68 处 ❌ | 保密 + 合规 |
| 引线交叉 | = 0 | 待测 | 制图规范 |
| 非 CONTINUOUS 实体 / 图层 | = 0 | 0 ✅ | 沿用现有 |

阈值先按上表落地，再用评测集回归调整；**阈值本身进版本控制，改阈值要留痕**。
